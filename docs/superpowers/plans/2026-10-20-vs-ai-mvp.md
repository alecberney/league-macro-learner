# League Macro Learner: vs-AI MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a playable browser game where one player commands the blue team against a rule-based AI (10 rank levels) through 37 simultaneous-order rounds, ending with a verdict at 25:10. Teaching mode can be switched on to explain each round.

**Architecture:** There are three Bun workspaces with one-way dependencies, `web → engine → data`.
- `data` holds JSON game values, their TypeScript types and a validating loader.
- `engine` is pure TypeScript with no DOM. It exposes `detectContacts` and `resolveRound` (deterministic), `viewFor` (fog of war), the AI and teaching explanations.
- `web` is Preact + @preact/signals + SVG. It only displays a `PlayerView` and collects orders.

**Tech Stack:** Bun (runtime, workspaces, dev server, bundler, `bun:test`), TypeScript (strict), Preact, @preact/signals, GitHub Actions CI.

**Spec:** `README.md` (approved design). Visual and map reference: `docs/game-screen-mockup.html`.

## Global Constraints

- Runtime and tooling: Bun only (no Node, Vite or Jest). Install Bun first if `bun --version` fails (`brew install oven-sh/bun/bun`).
- Dependencies go one way: `packages/web` → `packages/engine` → `packages/data`. `engine` must not import `preact` or touch `document`/`window`. `data` must not import `engine`.
- The engine is deterministic. All randomness goes through `Rng` (seeded mulberry32), so the same inputs give the same outputs.
- Game values (timers, weights, gold, XP, mistake rates, teaching texts) live in `packages/data/data/*.json`, never as literals in engine code.
- The game ships static assets only. Runtime code never calls Riot, Data Dragon or CommunityDragon. The fetch script downloads images into `packages/web/public/assets/`.
- There are 37 rounds over 5 phases: 1:30→3:30 (20 s), 3:30→6:10 (20 s), 6:10→14:10 (40 s), 14:10→20:10 (60 s), 20:10→25:10 (60 s). Phases 1–5 map to stages 0–4 (*really early, early, mid, mid-late, late*).
- Moves per round: laners 1, junglers 2. Ward limit: 3 per team per round. Unward limit: 1 per team per round, jungler or support only.
- Teamfight means 7 or more champions in a fight. Tower HP is 5. Push damage by number of champions is `[1,1,2,3,4]`. Herald removes 3 HP. Voidgrubs multiply tower damage by 1.5 (permanent), Baron by 2 for 3 rounds, and the two stack. Plates give gold until 14:00 (840 s).
- UI text is in French. Code identifiers and data keys are in English.
- The legal notice "League Macro Learner n'est pas approuvé par Riot Games…" is shown in the web footer.

## Review Focus

- A dead or respawning champion receives a normal move order, or is clickable as if alive. The expected behavior: it is rejected by validation, and the UI offers only spawn points. *(Task 5, Task 14)*
- A flee sends a champion back to a position that now holds an enemy. The expected behavior: no second contact is triggered in the same round, and the champion just stands there. *(Task 6)*
- The Herald carrier dies before launching. The expected behavior: the Herald is lost and no damage is applied. *(Task 9)*
- Round 37 resolves and the game must end. The expected behavior: no round 38, `state.over` is set, and an exactly equal score gives `winner: 'draw'`. *(Task 10)*
- AI orders across many seeds and ranks are always valid. The expected behavior: `validateOrders` never throws on AI output, and the AI never reads hidden enemy positions. *(Task 12)*

  ```ts
  resolveFight(state: GameState, data: GameData, position: string, blue: string[], red: string[], stage: Stage): { winner: Side | null; scores: Record<Side, number> }
  ```
  The score formula, with weights `W = rules.fight`:
  - `n = ids.length`, plus `W.towerNumbersFactor` if `towerFor === side`. The tower's side is the owner of a standing tower at `position`.

  - `score = W.numbers[stage] * n + W.lead * Σ lead(c)/1000 + W.matchup * Σ matchupTerm(c) + W.strength * Σ strength`

  The winner has the strictly higher score, using an epsilon of 1e-9. An equal score gives `null`.

**Files:**

**Interfaces:**
- Consumes: `PlayerView`, `reachable`/`spawnPoints` (they take a `GameState`, so add view-safe overloads `reachableFrom(data, position, moves)` and `spawnPointsFor(view, data, championId)` to `movement.ts`).
- Produces:
  ```ts
  evaluate(view: PlayerView, data: GameData): number    // ally lead sum - estimated enemy lead + objective/tower values + wave pressure
  aiOrders(view: PlayerView, data: GameData, profile: AiProfile, rng: Rng): Order[]
  aiContactChoice(view: PlayerView, data: GameData, contact: Contact, profile: AiProfile, rng: Rng): Choice
  ```
  Heuristics in `heuristics.ts` produce scored candidate orders per champion. Each mistake id switches one rule when `rng.next() < profile.mistakes[id]`, rolled once per champion per round.

  | Rule | Correct behavior | `MistakeId` flips it to |
  |---|---|---|
  | push / farm | stay in lane, step onto enemy front tower when wave is there and enemy jungler seen ≥2 rounds ago is far | `greed`: keep pushing even with jungler unseen |
  | objective setup | move to pit 1 round before spawn when lane wave ≥ 0 for our side | `objectiveTiming`: ignore spawns; `rotateWithoutPriority`: rotate even when wave is at our tower |
  | invade | only when enemy jungler last seen on the opposite side | `pointlessPlay`: random invade / random roam |
  | recall | when gold ≥ 1100 and wave at enemy side or 0 | `badRecall`: recall when wave at own tower, or never |
  | wards | ward pits 1 round before spawn, jungler/support unward on pits | `poorVision`: no wards |
  | after a won fight | take tower/objective on that position next round | `noConversion`: walk back to lane |
  | jungler tracking | avoid ganking side where enemy jungler was last seen ≤1 round ago | `ignoreJungler` |
  | contact choice | fight only if `fightScore` says we win with our visible information, else flee | `chasingKills`: fight when outnumbered |

  If `profile.lookahead > 0`, take the top 3 candidate sets, simulate them with `resolveRound` on a state rebuilt from the view (enemies at `lastSeen` positions and staying put) for `lookahead` rounds, and keep the best by `evaluate`.

- Produces:
  ```ts
  type Screen = 'start' | 'orders' | 'contacts' | 'review' | 'over';
  interface Settings { rank: Rank; teaching: boolean; seed: number }
  createStore(data: GameData): {
    screen: Signal<Screen>; view: Signal<PlayerView | null>; selected: Signal<string | null>;
    pending: Signal<Record<string, Order>>; contacts: Signal<Contact[]>; choices: Signal<ContactChoices>;
    lastEvents: Signal<GameEvent[]>; explanations: Signal<Explanation[]>; settings: Signal<Settings>;
    start(s: Settings): void; select(id: string | null): void; reachableForSelected(): Record<string, number>;

    confirmRound(): void; choose(contactId: string, choice: Choice): void; confirmContacts(): void; next(): void;
  }
  ```
  - The full `GameState` stays private in the store. Components only receive `view`.
  - `setMove` to a 2-step target picks `via` as the first shortest-path intermediate. When the jungler's `clearSpeed` reaches `fastClearAt`, it prefers an alive own camp.
